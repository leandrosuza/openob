para usuarios segue a segurança 

1. Autenticação e Identidade
Hash de Senhas: Criptografar senhas com algoritmos seguros (Argon2, bcrypt).

Tokens JWT Curtos: Definir tempo de expiração curto para os tokens de acesso.

Refresh Tokens Seguros: Usar tokens de renovação salvos em cookies seguros (HttpOnly).

Proteção de Tokens: Guardar tokens no cliente de forma a evitar vazamentos (XSS).

Autenticação em Duas Etapas (2FA): Exigir segundo fator para logins e ações críticas.

2. Autorização e Permissões
Controle de Acesso (RBAC): Restringir rotas conforme o perfil do usuário (ex: admin, cliente).

Validação de Dono do Recurso: Impedir que um usuário acesse ou altere dados de outro alterando o ID na URL.

Menor Privilégio: Conceder apenas os acessos estritamente necessários.

3. Proteção de Dados
Uso Obrigatório de HTTPS: Criptografar todo o tráfego da API em trânsito.

Ocultação de Dados Sensíveis: Nunca retornar senhas ou documentos nas respostas da API.

Validação de Entradas: Filtrar e sanitizar todos os dados enviados pelo usuário.

4. Proteção Contra Ataques
Limite de Requisições (Rate Limit): Bloquear acessos excessivos para evitar ataques de força bruta.

Bloqueio de Tentativas Falhas: Bloquear a conta ou pedir CAPTCHA após erros repetidos de login.

Cabeçalhos de Segurança: Configurar headers HTTP de proteção nas respostas da API.

Configuração de CORS: Restringir quais domínios externos podem acessar a API.

5. Gestão e Monitoramento
Logs de Segurança: Registrar tentativas de acesso e falhas (sem salvar senhas nos logs).

Invalidação no Logout: Cancelar a validade do token/sessão ao fazer logout.

Recuperação de Senha Segura: Enviar links de redefinição com tokens temporários e de uso único.

Versionamento de API: Manter rotas versionadas (/v1/) para atualizar falhas com segurança.

Atualização de Bibliotecas: Manter dependências do projeto sempre atualizadas.
